This supports the earlier finding that the largest stalls occur in the original
platform size callback before the renderer rebuild. It further locates the large
wall gap between native message callbacks, rather than within the measured
WM_SIZE or paint handlers. It does not establish a DWM, driver, scheduling or
specific native API root cause. The new hooks add overhead, so differences from
the 00:50 distribution must not be attributed solely to application behavior.

The next useful evidence is a system trace with UI-thread scheduling and call
stacks aligned to a slow native size callback. Repeating only the same JSONL
capture cannot resolve the remaining wait/scheduling attribution. Resize and
presentation policy should remain unchanged until that attribution is available.

Analysis also exposed a PowerShell overload issue: `Math.Max(0, residual)` selected
an integer overload and rounded residual milliseconds. The analyzer now explicitly
uses doubles; a fractional-residual regression fixture passes. This correction
affects derived output only and requires no recapture.
